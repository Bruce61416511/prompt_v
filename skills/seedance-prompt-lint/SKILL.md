# Seedance 提示词质检器

**职责单一：只检查，不生成。** 输入一段视频提示词，输出一份「哪有问题、怎么改」的质检报告。

## 何时使用

- 用户说：质检提示词 / 检查提示词 / 提示词自检 / lint 提示词 / 这条提示词有问题吗 / 帮我挑错 / 检查一下这段提示词
- 用户要的是一条**可直接拿去生成视频的成稿**时，与负责写的那条场景技能一起被选中，生成完立刻跑一遍。

## 不做什么

- 不重写整条提示词。只指出问题 + 给出**局部改法**
- 不擅自修改用户原文。改法以"建议"形式给出，由用户决定是否采纳
- 不评价创意好坏、不评价审美。只查**结构性缺陷和可执行性缺陷**
- 不因"看起来不错"就放行。**宁可否决，不可放过**

---

## 第 0 步｜先分清手上这条是哪种方言

两条技术路线写出来的提示词长得很不一样，**该查什么也因此不同**。先判断，再动手。

| | **goodcase 方言**（本仓 27 条场景技能走这条） | **即梦官方方言** |
|---|---|---|
| 结构 | 全局块 / 固定块 / 时间轴块 / 全局约束块；或 `【风格】【时长】【场景】【角色】【全局约束】` + 时间轴 | 四段式：`【素材描述】+【一句话概述】+【具体情节描述】+【全局补充】` |
| 机位术语 | **中英混写**：段头括号里留英文原词（`Ground-level Low Angle`），正文用中文 | 中文官方词表（推镜头 / 摇镜头 / 环绕拍摄……） |
| 音效 | 自然语言：`音效：轮胎压水的沙沙声` | 符号：音效 `< >`、音乐 `· · ·`、台词 `{ }`、字幕 `【 】` |
| 参考素材 | 文字描述"上传的图片是唯一视觉参考" | `@图片1` / `@视频1` / `@音频1` 编号引用 |
| 景别 | 中文（中景/近景/特写）或英文大写（`MEDIUM SHOT` / `CLOSE-UP`） | 中文官方词表 |

**判断方法**：找 `【一句话概述】` 或 `@图片N`。有 → 官方方言；只有分块结构 + 时间轴 → goodcase 方言。

> ⚠️ **判错会怎样**：拿官方方言的尺子去量 goodcase 方言的提示词，会把「缺【一句话概述】」「音效没用 `< >`」报成硬伤 —— 但这两项 **goodcase 路线压根不要求**，照着改反而会把好提示词改坏。
>
> 实测过一组：3 份 goodcase 方言的提示词，共 12 项被原版判「必改」，其中 3 项属这类误报（缺概述 3/3、声音符号 2/3）。

## 检查项分两类

### A 类｜通用检查（**无条件跑**，两种方言都适用）

查的是「提示词能不能被执行」，与格式无关。**这一层是本 skill 的主要价值。**

#### 结构层

| # | 检查项 | 判定方法 |
|---|---|---|
| S1 | **有无时间戳** | 匹配 `\d+\s*[-–~]\s*\d+\s*秒`、`[00:00-00:04]`、`第\s*\d+\s*帧`。超过 15 秒的提示词必须有；短于 8 秒可无 |
| S2 | **时间段连续不重叠** | 解析所有区间：① 首段从 0 开始 ② **段间无断档** ③ 无交叉重叠 ④ 末段终点 = 目标时长。⚠️ 最常见的硬伤是「0-3 → 4-7 → 8-11」这种**每段之间空一秒** |
| S3 | **每段有无运镜** | 每段都必须有。**"固定镜头"也是运镜**，也要写出来 —— 不写，模型可能自行加运动。英文写法（`locked-off` / `static frame` / `handheld`）同样算数 |
| S4 | **每段有无景别** | 中文（大远景/远景/全景/中景/近景/特写/大特写/微距）或英文大写（`WIDE` / `MEDIUM SHOT` / `CLOSE-UP` / `MACRO`）。允许"保持上一镜"。**整条从头到尾无景别 → 必报** |
| S5 | **有无反向描述** | 查找"无字幕""不要字幕""无 BGM""无水印""禁止""不出现"等。缺失即漏项 |
| S11 | **有无声音层** | 整条提示词**完全没提声音** → 提醒。写了音效行、写了环境声、或明确声明"无对白无音乐"都算通过。**静音也要写出来，不要留空**——留空会让模型静默输出或自行乱加 BGM。片型以声音为主要质感时（ASMR / MV / 定格动画 / 咀嚼音），在提醒里写明"强烈建议补" |
| S8 | **总时长与段落匹配** | 各段时间之和 = 声明时长；单段内容量 > 3 个事件也要提醒 |
| S9 | **是否含过期参数** | 仍写"≤15秒""≤9张图""≤12个文件" → 提醒。正确值：30 秒 / 30 图 / 10 视频 / 10 音频 / 总 50 |
| S10 | **违规/敏感表述** | 医疗功效（"治疗""改善""调理"）、绝对化用语（"最""第一"）、未授权品牌与真人姓名 → 必改 |

#### 语义层（**本 skill 的核心**：语法挑不出、但语义有问题）

| # | 检查项 | 典型病症 |
|---|---|---|
| M1 | **动作是"变化过程"还是"静态状态"** | ❌"水珠凝结在瓶身"（状态）→ ✅"水珠沿瓶身缓缓滑落，留下湿痕"<br>❌"雾气升腾"（模糊）→ ✅"雾气从瓶口逸出，逐渐散开"<br>❌"产品定格"（无动作）→ ✅"光线向瓶体顶部收拢，画面静止两秒" |
| M2 | **运镜是否说清"从哪到哪 + 怎么动"** | ❌"镜头回到产品特写"（只说位置）→ ✅"镜头以中景缓慢推入产品特写"<br>❌"环绕拍摄"（无客体）→ ✅"镜头以产品为中心顺时针环绕半圈，始终保持产品居中" |
| M3 | **一句话概述是否五要素齐全** | 仅当这条提示词本来就有概述句时检查。要素：主体 + 地点 + 事件 + 题材/风格 + 特殊运镜。**goodcase 方言通常没有这段，不要因此报缺项** |
| M4 | **画面内容是否具体** | ❌"画面很美""高级感十足""非常震撼"（空词）→ 换成可观察的：主体、材质、光线、动作、空间关系 |
| M5 | **人物动作是否有可观察表现** | 只写"她很开心"→ 提醒改为可见表现：眼神、眉头、嘴角、呼吸、手部动作。单次情绪转折选 2-4 个表现 |
| M6 | **每段是否只有"一个主要变化"** | 单段塞 3 个以上事件 → 提醒拆段 |
| M7 | **相机是否遮住关键动作** | 花哨运镜挡住主体动作 → 提醒简化或延后运镜。**也包括"运镜与动作互相打架"**：例如同段里既写"镜头拉远"又写"人物驶出画面"，而下一句又说"人与车缩到画面下三分之一"—— 三者空间上互斥 |

#### 一致性层

| # | 检查项 |
|---|---|
| C3 | **同一主体是否统一绑定**：跨场景出现的同一人物，是否始终用同一组素材编号 / 同一段身份描述 |
| C4 | **术语是否可执行**：自造词（`电影感运镜` `高级运镜` `炫酷镜头` `大片质感运镜`）→ 必换具体术语。**英文机位原词是合法写法，不算自造词** |

### B 类｜官方格式专项（**只有确认是官方方言时才跑**）

| # | 检查项 | 触发条件 |
|---|---|---|
| S6 | @引用编号连续（`@图片N` 从 1 起、无跳号） | 提示词里出现了 `@图片/@视频/@音频` |
| S7 | @引用是否声明用途 | 同上。禁止只写"参考@视频1"而不说参考什么 |
| C1 | 是否符合官方四段式 | 用户明确要求「按即梦官方格式写」 |
| C2 | 素材映射是否逐一命名 | 有多个参考素材时。禁止"@图片1至@图片4分别定义四名角色"这种模糊写法 |
| C5 | 声音符号是否正确 | 用户明确要求使用官方符号体系 |
| C6 | 禁止项是否开头声明 + 结尾重申各一遍 | 用户明确要求官方格式 |

> **B 类结果不计入「必改」**，单独归到「📐 格式备注」栏。goodcase 方言的稿子，这一栏可以整栏忽略。

## 输出格式

```markdown
## 质检报告｜<提示词标题或首句摘要>

**方言判定**：goodcase 方言 ／ 官方方言 —— 依据：<有没有【一句话概述】或 @图片N>
**结论**：❌ 必改 N 项 ｜ ⚠️ 提醒 N 项 ｜ 📐 格式备注 N 项 ｜ ✅ 通过 N 项

---

### ❌ 必改（A 类缺项，不补会出问题）

**1. <问题标题>**
- 位置：<第几段 / 哪一格>
- 问题：<引用原文片段> + 说清为什么不行
- 建议改为：`<可直接抄的改法>`

---

### ⚠️ 提醒（A 类语义层，需人工判断）

**1. <问题标题>**
- 位置：
- 问题：
- 建议改为：`<改法>`

---

### 📐 格式备注（B 类。仅当你要官方格式时才需要改 → goodcase 路线可整栏忽略）

**1. <问题标题>**
- 位置：
- 问题：
- 若要官方格式，建议改为：`<改法>`

---

### ✅ 通过

<一行一条，列通过项即可>

---

### 总评

<一句话：最该先改的是哪个>
```

**分类标准：**

| 级别 | 判定 | 处理 |
|---|---|---|
| ❌ **必改** | **A 类**结构性缺失（整段无运镜、无景别、时间段断档、无反向描述、违规表述、自造词） | 必须改，否则会翻车 |
| ⚠️ **提醒** | **A 类**语义可疑（动作偏静态、画面偏空、事件过密、运镜与动作打架） | 用户判断，可不改 |
| 📐 **格式备注** | **B 类**，官方格式专属 | 只在用户要官方格式时才需要处理 |
| ✅ **通过** | 该有的都有 | 不用管 |

**A 类的语义层结果一律归入 ⚠️ 提醒，不做否决**——因为语义判断有波动，最终由人定夺。

---

## 检查时的纪律

1. **先判方言，再逐段过。** 不判方言就开查，最容易把 B 类当 A 类报。
2. **逐段过，不跳段。** 每段的时间 / 景别 / 运镜 / 画面 / 动作五项都要过一遍。
3. **引用原文。** 指出问题时必须引用原句，不能只说"第 3 段有问题"。
4. **给可抄的改法。** 不能只说"这里要改"，要给出一句能直接替换的文字。
5. **不凑数。** 没问题就写"通过"，不要为了显得认真而强行挑刺。
6. **不放过明显漏项。** 整段没运镜、整条没景别、时间段断档这类，一定报。
7. **A 类必须跑完。** 不要只跑几个表面项就交差。

## 附：本 skill 的由来与改造

### 由来

2026-10-15，一次真实复盘：给「百芙乐后生元饮品」写 30 秒广告提示词时，出现 5 处缺漏，而**官方 skill 里其实早有正确写法**——问题不是知识缺失，是**缺少一层检查**。

本 skill 就是补这层检查。设计原则：**宁可多报一句提醒，不可漏过一个缺项。**

### 2026-10-16 改造（v2.0.0）

原版只认**即梦官方四段式**这一种格式，而本仓 27 条场景技能走的是 **goodcase 案例方言**。
实测 3 份本仓产物（雨夜骑手 / 定格动画 / 可口可乐广告），原版共报 12 项「必改」，其中：

| 类型 | 数量 | 说明 |
|---|---|---|
| 真问题 | 8 | 时间段断档 3 秒、全片无景别、5 段无运镜、整条无声音层、单段 5 事件、运镜与动作互斥…… |
| 格式误报 | 3 | 缺【一句话概述】3/3（goodcase 路线不要求）、声音未用 `< >` 2/3 |
| 字面主义 | 1 | 抠"固定机位"四个字里没有"固定镜头" |

**改造动作**：把检查项拆成 A 类（通用，无条件跑）和 B 类（官方格式专项，条件跑），
B 类结果降级为「📐 格式备注」，不混进「❌ 必改」。
同时给 S3/S4/C4 补上英文写法白名单，避免把 `MEDIUM SHOT` / `lock-off` 判成缺失。
