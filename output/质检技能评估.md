## 二、抓到的真问题（格式无关，确实会翻车）

### 🔴 重大：可口可乐那条的时间段有断档

原文写的是 `0-3秒 → 4-7秒 → 8-11秒 → 12-15秒`，
**中间漏掉了 3-4、7-8、11-12 三秒**。lint 原文：

> 段间出现 `3-4秒`、`7-8秒`、`11-12秒` 三处空档，模型无法判断这三秒该生成什么。

这正是时间轴技能里写明的那个坑的变体（"写 30 秒却只列到 24 秒，模型会把最后一段拉长填满"）。
**而这条提示词是用原装 `seedance-prompt-library` 生成的——那个技能不强制分段校验，所以漏了。**

### 🔴 定格动画那条：结构层几乎全空

| lint 报的问题 | 判定 |
|---|---|
| 全片无时间戳，5 个动作段与时长完全脱钩 | **真问题** |
| 全片没有任何景别词（全景/中景/近景/特写） | **真问题** |
| 5 个动作段没有一段写明"本段镜头保持固定" | **真问题** |
| **整条完全没有声音层**（定格动画的咔哒节奏感是核心质感） | **真问题** |
| 第 3 段塞了 5 个事件（发现→起跳→四腿张开→空中定格→落地） | **真问题** |
| 第 4 段 `lands` 是瞬时状态不是变化过程 | **真问题** |

### 🟡 雨夜骑手那条：抓出一个真矛盾

> 镜头 5 同一段里既写「镜头缓缓向后上方拉远」，又写「他……拧动车把**驶出画面** → 镜头继续拉远」，
> 且「驶出画面」与「镜头拉远后人与车缩到画面下三分之一」在空间上矛盾（驶出画面就不该还在画面里）。

这个**我人工复核确实成立**——是同段里两个描述互斥。

另外还抓出：镜头 4 在 3 秒里塞了 5 个事件、镜头 1 前半段偏静态、镜头 5 运镜只说方向没给落点。

## 三、误报（官方格式专属，我们的技能根本不用那套）

lint 的底子是**即梦官方四段式**：`【素材描述】+【一句话概述】+【具体情节描述】+【全局补充】`，
外加官方声音符号体系（音乐 `· · ·`、音效 `< >`、台词 `{ }`、字幕 `【 】`）。

**我们这一整套技能用的是 goodcase 案例方言** —— 实测确认：

```
$ grep -rl "四段式|素材描述|一句话概述|具体情节描述|全局补充" skills/     → 空
$ grep -rn "· · ·|< >|{ }|【 】" skills/*/SKILL.md                        → 空
```

于是必然产生格式误报：

| lint 报的项 | 3 份里报了几次 | 实际是不是问题 |
|---|---|---|
| C1 缺【一句话概述】/ 不符官方四段式 | **3/3** | ❌ 误报——我们的技能从不要求四段式 |
| 声音未用官方符号 `< >` | **2/3** | ❌ 误报——我们技能里音效就是自然语言 |
| S3 抠字眼：「固定机位」四个字里没有「固定镜头」 | 1/3 | ⚠️ 字面主义 |
| C6 禁止项没"开头声明+结尾重申"各写一遍 | 2/3 | ⚠️ 官方建议，非硬性 |
| S6/S7 `@图片N` 引用 | 0/3（无参考图） | 只在有参考图时才有意义 |

**误报率**：三次共 12 项「必改」里，真问题 8 项、格式误报 3 项、字面主义 1 项。

## 四、为什么它对新技能反而是最需要的

对比一下「新技能强制了什么 / 没强制什么」：

| 检查项 | 14 个新技能有强制吗 | lint 能补吗 |
|---|---|---|
| 时间分段首尾相接、总和=声明时长 | ✅ **时间轴技能强制** | 补（可口可乐那条就是漏的） |
| 固定块写一次防外观突变 | ✅ 强制 | — |
| **逐段景别** | ❌ **没有任何技能强制** | ✅ 能补 |
| **逐段运镜（连固定镜头也要写明）** | ❌ 不强制（机位写在段头括号里，但不是"运镜"字段） | ✅ 能补 |
| **声音设计完整性** | ❌ 不强制 | ✅ 能补 |
| 单段事件密度 ≤ 1 个主要变化 | ⚠️ 只有时间轴技能提了 | ✅ 能补 |
| 动作是"变化过程"而非静态状态 | ❌ 没有技能强制 | ✅ 能补 |

**结论：新技能在"时间分割"这一项上很严，但在"景别 / 逐段运镜 / 声音设计 / 事件密度"这四项上完全没有要求 —— 而这四项正是 lint 第 2 层语义层的强项。**

定格动画那条就是活证据：它出自新技能，时间轴虽然也没有，但**景别、逐段运镜、声音层三样全空**，lint 一次全抓出来了。

## 五、结论与三个方案

### 判断：**有作用，但不能原样装。**

- **值**：第 2 层语义层（M1 静态当动作 / M2 运镜只说位置 / M6 事件过密 / M7 运镜遮动作）+ S2 时间连续性 + S4 景别 + 声音完整性——这几项抓出的**都是会让成片直接翻车的硬伤**，而且和格式方言无关。可口可乐那条 3 秒断档就是明证。
- **坑**：它的第 1 层和第 3 层有一半是"即梦官方格式"专属检查，会给我们 goodcase 风格的提示词刷误报。如果生成后全盘照收 lint 的建议去改，**反而会把好提示词改坏**（比如硬塞一个【一句话概述】段、把"音效：雨声"改成 `<雨声>`）。

### 三个方案

| 方案 | 做法 | 代价 |
|---|---|---|
| **A（推荐）** | 装进来，**改它的 SKILL.md**：把 C1 / C5 / C6 / S6 / S7 这五项官方格式专属检查标成「仅当用户明确要求官方四段式格式时才检查」，保留 S2/S3/S4/S5/S8/S10 + 全部 M1-M7 | 改一次 SKILL.md，约 20 行 |
| **B** | 原样装，每次质检后人工筛掉格式误报 | 每次多读几行，有把好提示词改坏的风险 |
| **C** | 不装 | "时间段断档""全片无景别""无声音层"这类硬伤没人抓 |

### 一句话

**装，但要按方案 A 改造**——把「官方格式合规」和「提示词可执行性」两件事拆开：前者是它自带的口味，后者才是我们真正缺的那层检查。

> 附带一个副作用要留意：装进 `skills/` 后它会出现在「挑技能」清单里。
> 它的 description 里写了「也应在任何 skill 生成完视频提示词后主动调用」——
> **这句话可能让模型在只需要写提示词的时候也顺手选上它**，多注入约 3,700 字符。
> 装好后需要重跑一遍 `scripts/test_pick_skills.py` 的 23 项，看有没有被误选。
